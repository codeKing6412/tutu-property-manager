# 图图物业管家

本项目为单机物业管理工作台，业务数据使用 SQLite 保存在本地。运行仅需 Python 3.10 或以上版本，无需数据库服务器、联网服务、账号或 npm 安装。本机已具备运行环境。

GitHub 私有仓库：<https://github.com/codeKing6412/tutu-property-manager>。仓库只保存程序与文档，`data` 正式账本和 `qa-output` 演示账本不会上传。

## 启动

双击项目根目录的 **启动物业系统.bat**。浏览器会打开 <http://127.0.0.1:8877>。重复双击会打开现有服务，不会重复启动。

关闭浏览器不影响后台服务；Windows 重启后重新双击启动。要结束后台服务，双击 **停止物业系统.bat**。

项目路径：`D:\Workspace\project\project\property`。

## 首次使用顺序

1. 进入“系统设置”：配置小区名称、默认起算日期、物业费单价、停车费提醒天数，以及常用住户身份、收款方式。
2. 新增或批量导入房屋，再导入业主、车位和车辆。当前正式账本已经包含用户导入的数据，请勿用演示库覆盖。
3. 进入“车位管理”，维护车位状态及其默认停车管理费、公共收益；再到“费项配置”新增垃圾费、公共能耗、指定车辆特殊费等规则。
4. 在“收费中心”检查应缴账单；历史欠费可单独补录。
5. 选择账单，登记真实收款日期、收款方式和各项目金额。系统更新工作台，可打印收据。
6. 定期在“系统设置”下载完整备份，保存到其他磁盘。

## 房屋与档案

- 小区、楼栋、单元、门牌构成唯一房屋地址。批量导入后自动生成导航树；左树选节点，右表过滤对应房屋及业主、车辆。
- 一房可以关联多个业主或住户；一位业主可以关联多房。住户身份可在系统设置维护，也可录入时直接填写新名称，房屋可指定一位主联系人。
- 车辆必须指定归属房屋；可同时指定车主。所选车主必须与本房屋关联，避免一人多房时无法明确归属。
- 车位独立建档。车位状态名称、是否需要关联房屋、是否收管理费和公共收益均可维护。车辆与其车位必须属于同一房屋。
- 点击房号、车辆档案的车牌，可打开侧面详情卡；“房屋信息、业主信息、车辆信息”自上而下排列，多业主、多车辆可以下拉切换。
- 顶部搜索支持房号、姓名、手机号、证件号及车牌模糊匹配。输入车牌即可定位房号、业主及车辆。
- 编辑记录保存变更前后快照，可在操作记录查看。转让或换租时编辑关联并在备注记录交接日期；历史变更在操作记录及完整备份中保留。不是独立的产权合同或租约台账。
- 关联账单的房屋、车位、费项不能直接删除；可停用以保留历史账目。停用不会取消已生成账单。

## 收费规则

### 单价和金额

- 物业费 = 建筑面积 × 单价（元/㎡/月）。每套房屋可覆盖默认单价。
- 停车年度收费拆成两张账单：车位管理费默认480元/年，停车公共收益默认1320元/年。缴费时可“一次按年缴纳”，收据和年度核算仍分别列出两项。
- 每个车位可以分别覆盖管理费和公共收益金额。留空使用其车位状态的默认值，填0表示该车位该项免收。
- 车位状态可以自由命名和新增，并分别控制是否自动收取管理费、公共收益，以及是否必须关联房屋。
- 收费规则可应用于全部房屋、整栋、整单元、单套房、全部车辆、指定车辆、某类车位或指定车位。
- 追加费项支持固定金额、按面积和按次；周期支持每月、每季度、每半年、每年、自定义每N个月、一次性和手动。
- 指定车辆的特殊收费直接建立“指定车辆”规则，账单自动归入车辆所挂靠的房屋。
- 临停：配置“按次 / 手动”费项，例如每小时3元，在收费中心选择此费项，数量填实际小时数。按单价×数量入账。当前不包含车辆进出识别、自动计时或阶梯封顶计价。
- 单独费率留空使用默认值；填0表示免收。
- 各账单使用十进制计算，四舍五入到分，付款以整数分记录，避免浮点累计误差。

### 出账和预缴

- 每月1日生成**下个月**物业费及周期性追加账单；年费只在下一个年度服务期起始月生成。
- 月中起算按整月计费；不按天折算。
- 页面打开时、运行跨日时检查出账；程序关闭期间的月份在下一次启动时补齐。
- 同一房屋、费项、账期不会重复生成账单。
- “生成预缴账单”选择目标月份，可快捷生成半年、一年、两年。以当前月开始连续计算快捷范围，也可手动选择目标月份，最多生成未来5年。
- 停车费以12个月为一个服务期。例如2026年9月起交一年，服务期为2026-09-01至2027-08-31，下一次续费日是2027-09-01。
- 下一年度停车账单在到期前已经生成时，工作台会在续费日前14天提醒；提醒天数可在系统设置改为1至31天。
- 系统从各费项起算月补齐至目标月，因此可一次从欠费状态缴至未来1—2年。
- 筛选房屋、具体费项、截止月份后，可缴纳筛选内全部待缴或勾选本页账单。
- 各账单可分别缴付、部分缴付；同一收款可涵盖多个费项、多个月份。填0跳过某张账单，不允许超收。
- 未来月份预缴体现在对应账单已缴金额，实际进账仍落在真实收款日期。
- **已生成账单锁定原金额**。后续单价、日期或归属修改不会重写历史和提前生成的账单；变更只影响尚未生成的账单。请确认费率后再提前生成远期账单。
- 单张账单可通过“调整”修改应缴金额或减免至0，必须填写原因并保留操作记录；调整后金额不能低于已收金额，已付款账单需先撤销相关收款。
- 历史欠费可在“补录 / 临停收费”自定义名称、应缴日期和金额。若同一期间已自动生成费用，不要再次补录以免重复。

### 统计口径

- 本日、本月、本季度、本年度进账：该期间实际收到的有效收款总额。
- 欠费总额：截至今天已到期账单的应缴减已缴；不包含未来未缴账单。
- 期间收缴率：到期日期位于所选期间的账单已缴金额 ÷ 应收金额。没有应收时显示“—”。后续补缴会提高历史期间账单的当前收缴率。
- 上月概览：上月实际进账及其费项构成，上月应收，以及上月账单截至今天仍未缴的金额。
- 柱状图展示最近六个月进账；甜甜圈图跟随工作台所选期间展示收款构成。
- 工作台“应收核算”支持本月、本季度、本年度、上年度、近12个月和自定义月份区间，并可继续按全部小区、整栋、整单元、单套房及费项组合筛选。
- 应收核算统一展示已出账应收、已经收回、尚未收回、到期欠费和收缴率；底部未收账单严格跟随同一组区间、范围及费项条件。
- 核算区间的已收按账单所属服务期统计：即使2025年账单在2026年补缴，也会计入2025年账单的已收金额；实际进账图仍按真实到账日统计。

### 撤销和退款

收款流水支持填写原因后整笔撤销 / 退款，原收款标记作废，全部关联账单恢复待缴。这里采用原单冲销口径，不生成独立的当日负向退款现金流。部分退款请先撤销，再重录实际保留金额。操作记录保留原因与原流水。

## Excel / CSV 导入导出

综合档案及车位页面可下载 `.xlsx` 模板、导出完整档案，并导入 `.xlsx` 或 UTF-8 / GB18030 编码的 `.csv`。读取 Excel 第一个工作表。

- 使用模板表头；不识别的额外列会忽略。
- “编号”是档案关联键，可自行指定，如 `H001`、`O001`、`S001`。留空由系统生成；填写已存在编号会更新该档案。
- 示例：房屋编号 `H001`；业主的“关联房屋编号”填 `H001`；车位的“计费房屋编号”填 `H001`，其编号设 `S001`；车辆关联 `H001`、业主编号和 `S001`。
- 一位业主关联多套房，用英文逗号分隔房屋编号，如 `H001,H002`。
- 先房屋，再业主，再车位，最后车辆。首次导入房屋时主联系人编号可先留空，导入业主后再设置。
- 日期推荐写成文本 `YYYY-MM-DD`，也支持带日期格式的Excel原生日期单元格。手机号、车牌和证件号也应使用文本格式，避免 Excel 丢失前导0或截断长号码；已经在源文件中丢失的数字无法恢复。
- 车位状态必须先在“车位管理”页面上方的“车位状态与默认年度收费”中存在并启用；默认提供“已售 / 已租 / 临停 / 空闲”，也可以新增任意名称。启用字段使用 `1` 或 `0`。
- 选择文件后先校验，错误提示包含行号。**任何一行失败，整批不写入**；校验通过后点击“确认导入”才提交。
- 单文件最大约8MB，较大档案请分批导入。

## 数据和备份

- 正式数据库：`data/property.db`。
- 服务日志：`data/server.log`、`data/server-error.log`。
- 完整备份：由浏览器下载 JSON，包含档案、设置、账单、收款、分摊关系及全部操作记录。下载目录由浏览器设置决定。
- 恢复前自动快照：`data/backups/before-restore-时间.db`。恢复失败时当前事务回滚，避免部分覆盖。
- 数据库、代码均在本项目 D 盘目录。Codex 自身状态、浏览器配置等可能仍由应用管理并写入 C 盘，不属于业务数据库。
- 界面操作记录展示最近300条；完整历史保存在数据库及备份内。

### 2026-09-06 收费规则升级

升级时检测到正式库已有421套房屋、425位住户、166辆车、154个车位和2笔收款，因此先保存了JSON和SQLite双重快照。旧版车位只有一个年度总价，升级按“保持每个车位原总额不变”拆分：总额不超过480元的全部计入管理费；超过480元的管理费为480元，其余计入公共收益。例如原1800元拆成480元管理费与1320元公共收益。183张旧版停车合计账单已拆分，原账单合计及付款分配总额保持不变。

车位起算日期为空时沿用系统默认起算日期。升级后原来带年度金额但未自动出账的车位，会按起算日期生成管理费和公共收益账单；请在工作台应收核算中按年度及房屋范围抽查实际口径。若需回看升级前状态，可使用 `data/backups/before-v2-upgrade-20260906-192044.json` 或同名 `.db` 快照。

## 验证与开发

```powershell
python -B -m unittest discover -s tests -v
node --check static/app.js
```

`tests/seed_demo.py` 创建独立演示数据库（仅虚构数据）；不会写入正式数据库。`tests/browser_v2.cjs` 验证自定义状态、整栋规则、指定车辆规则、停车费分项收款和灵活应收核算；`tests/production_smoke.cjs` 只读检查正式界面、核算金额及导入数据数量。测试工具安装于 `D:\Temp\GPT_Temp\property-qa`，不是运行系统的必要依赖。

如需手动启动独立演示服务：

```powershell
python -B tests/seed_demo.py
python -B server.py --port 8766 --no-browser --db qa-output/demo.db
```

日常使用只需双击启动入口，无需运行测试命令。
